# LP Structure — NEXORA AI LP

**凡例**: 【確定情報】client-brief.mdの記載事実 / 【AIによる分析・仮説】02_target_analysis.mdの心理分析 / 【AIによる提案】STEP03・STEP04でAIが考案した訴求・構成・ビジュアル・CTA配置(クライアント決定済みの方針ではない)

本文書は「どの順番で何を伝えるか」「各セクションがどのような視覚的役割を持つか」の設計のみを行う。HTML/CSS/JS実装、完成コピーの執筆はSTEP05以降で行う。

## 1. LP全体の設計方針

- **LPの目的**【確定情報】: 無料相談の申込み獲得
- **メインターゲット**【確定情報】: 中小企業の経営者・事業責任者・管理職。AI活用に興味はあるが何から始めればよいか分からない
- **コアポジショニング**【AIによる提案・STEP03】: 業務理解 → AI活用設計 → 導入支援 → 運用支援、という一貫した支援。「AIツールを売る」のではなく「AIを現場で使える形にする」支援として位置づける
- **CTA方針**【確定情報+AIによる提案】: 「無料相談を申し込む」を、HERO・FEATURES理解後・FINAL CTAの**3箇所のみ**に配置し、追加しすぎない
- **視覚方針**【AIによる提案】: 同じカードレイアウトを繰り返さず、セクションごとに背景・レイアウト・カードサイズ・UI表現を変化させ、スクロールに応じた視覚的な変化を作る。今時のBtoB SaaS/AIスタートアップサイトのトーン(Dark Navy・Blue・Cyan、Bento Grid、Dashboard mockup、floating UI、glassmorphism)を基調とし、FLEXIA・LUMIELより1段階上の作り込みを目指す

## 2. セクション一覧(全11セクション)

- SECTION 01: ファーストビュー(HERO)
- SECTION 02: ターゲットの悩み(PROBLEM)
- SECTION 03: 視点の転換(INSIGHT / CONCEPT)
- SECTION 04: 支援の全体像(SOLUTION / HOW IT WORKS)
- SECTION 05: 特徴(FEATURES・Bento Grid)
- SECTION 06: 中間CTA
- SECTION 07: 活用イメージ(USE CASE / USAGE IMAGE)
- SECTION 08: 導入後のサポート(SUPPORT)
- SECTION 09: FAQ
- SECTION 10: 最終CTA(FINAL CTA)
- SECTION 11: 架空制作であることの表記(FOOTER)

※料金・実績・お客様の声・比較表・導入事例の各セクションは、確定情報がない、または本タスクで明示的に禁止されているため設けない(詳細は本文書末尾「使用しないと判断した要素」を参照)。

## 3. 各セクション詳細

### SECTION 01：ファーストビュー(HERO)

【目的】
「AI活用を検討している自社向けのサービスだ」と一瞬で伝え、離脱を防ぐ。BtoB SaaSらしい作り込まれた第一印象を作る。

【この時点の読者心理】(仮説)
「AIを業務に活かしたいが、何から始めればいいか分からない」という漠然とした関心と迷い。

【伝える情報】
ブランド名、メインコピー、サブコピー、メインCTA、補助的なページ内サブCTA。

【確定コピー】
メインコピー「AIを、現場で使える仕組みに。」/ サブコピー「業務に合わせたAI活用を設計し、導入から運用までサポート。」/ CTA「無料相談を申し込む」

【AIによる提案】
メインCTAの下に、ページ内サブCTA「支援内容を見る」(SECTION04またはSECTION05へのアンカーリンク)を1つ設置してよい。ただし視覚的な優先度はメインCTAより明確に下げ、メインCTAを弱めない(サイズ・色のコントラストで区別する)。

【ビジュアル要素の想定・Dashboard UI構想】
- レイアウト: PC 2カラム(左=コピー・CTA、右=Dashboard mockup)。Mobileは縦積み(コピー→CTA→Dashboard mockupの順)
- 右側: 架空のSaaSダッシュボード風UIを想定。**売上・削減率・成功率・満足度・導入件数・ROI・パーセンテージ・架空の数値グラフは一切使用しない**
- Dashboard mockupの表示要素(すべて状態ラベルであり数値実績ではない):
  - カード1: ラベル「WORKFLOW」+ ステータス「ACTIVE」
  - カード2: ラベル「AI ASSIST」+ ステータス「CONNECTED」
  - カード3: ラベル「PROCESS」+ ステータス「READY」
  - カード4: ラベル「SUPPORT」+ ステータス「ACTIVE」
  - 補助要素: 抽象的な接続線・ノード風の装飾(業務とAIが連携しているイメージ)、意味のある数値を伴わないプログレスバー風の装飾(進捗の"雰囲気"のみ、実数値・パーセンテージ表示はしない)
- 背景: Dark Navyを基調に、Blue〜Cyanのsubtle gradient・glow・blur・grid線・light particle風の装飾を組み合わせる。SF映画的な過剰さは避け、実際に企業へ提案できるリアルなBtoBトーンに留める
- 装飾: floating UI card風にDashboard要素を数枚重ねて浮遊させる、gradient border、subtle glassmorphism

【Mobile再構成方針】
Dashboard mockupは単純縮小せず、カード4枚を横並びのカルーセル風、または2×2グリッドに再構成する。文字サイズ・タップ領域を確保し、375px幅でも横スクロールを発生させない。

【CTA】
あり(メイン)。「無料相談を申し込む」。理由: 来訪直後の関心が高いタイミングでまず選択肢を示す。サブCTA「支援内容を見る」も補助的に配置。

【次セクションへの役割】
「何から始めればいいか分からない」という関心を受け、次のセクションで具体的な悩みへの共感を示す。

### SECTION 02：ターゲットの悩み(PROBLEM)

【目的】
ターゲットに「これは自社のことだ」と感じてもらう。

【この時点の読者心理】(仮説・02より)
「AIという言葉は知っているが、自社の業務とどう結びつくのか分からない」という迷い。過去のツール導入が定着しなかった経験・懸念(仮説)。

【伝える情報】
client-brief.md記載の悩み(AIを導入したいが活用方法が分からない/どの業務をAI化できるか分からない/社内にAIの専門人材がいない/AIツールを導入しても使いこなせるか不安/業務効率化を進めたい)。

【見出し方向性】
「AIを使いたい。でも、何から始めればいいか分からない。」を軸とした問いかけ型の見出し。

【使用可能な確定情報】
client-brief.md記載の5つの悩み。

【AIによる提案】
5つの悩みを、単純な均等カードではなく「issue chip」風の短いタグ表示+補足文の組み合わせで見せる。FLEXIA/LUMIELのチェックリスト型カードとは異なる見せ方で差別化する。

【ビジュアル要素の想定】
背景はDark Navy寄りの暗いトーン(HERO直後に暗→暗という連続を避けたい場合は、Sub Background的な濃紺グレーに調整する余地をSTEP06に残す)。issue chip(角丸の小さなタグ)を並べ、ホバー/タップで補足説明が見える程度の軽いインタラクションを検討可。警告色(赤)は使用しない。

【Mobile再構成方針】
issue chipは横スクロールのタグ列ではなく、縦積みの1列リストに再構成し、375pxでも横スクロールを発生させない。

【CTA】
なし。共感段階での早すぎるCTAは唐突なため。

【次セクションへの役割】
悩みへの共感を踏まえ、視点の転換(INSIGHT)へ接続する。

### SECTION 03：視点の転換(INSIGHT / CONCEPT)

【目的】
「AIツールから考える」のではなく「まず業務から整理する」という視点を提示し、コアポジショニングへの導入とする。

【この時点の読者心理】(仮説)
「そもそも自分たちは何を検討すればいいのか」という迷いに対し、新しい切り口を求めている。

【伝える情報】
AIツールの選定から入るのではなく、業務理解から入るという考え方(STEP03コアポジショニングの言語化)。

【見出し方向性】
大きめのタイポグラフィで短く言い切る見出し(例: 「AIツールから、ではなく。業務から。」のような対比構造。最終文言はSTEP05で確定)。

【使用可能な確定情報】
業務ヒアリングから始まるという確定特徴(次セクションの布石として言及可)。

【AIによる提案】
カード・リストを使わず、大きなタイポグラフィと余白のみで見せる「Large typography + minimal visual」のセクションとする。SECTION02(暗く情報量の多いissue chip)からの反動として、静かで印象的な間を作る。

【ビジュアル要素の想定】
背景はDark NavyまたはBlueグラデーションの単色に近い落ち着いたトーン。装飾は最小限(細いグリッド線、または1本のglowラインのみ)。

【Mobile再構成方針】
タイポグラフィサイズを縮小しつつ、余白比率は維持する。装飾要素はMobileでは非表示または大幅に簡略化してよい。

【CTA】
なし。

【次セクションへの役割】
「業務から考える」という視点を踏まえ、具体的な支援の全体像(SOLUTION/HOW IT WORKS)へ接続する。

### SECTION 04：支援の全体像(SOLUTION / HOW IT WORKS)

【目的】
NEXORA AIの支援内容を、確定情報のみで構成された一連の流れとして理解してもらう。

【この時点の読者心理】(仮説)
「具体的にどんな支援をしてくれるのか」を知りたい。

【伝える情報】
業務ヒアリング → AI活用方法の提案 → 業務フローに合わせた導入支援 → AIツール活用支援 → 導入後の運用サポート、という5段階の流れ。**具体的な期間・回数・担当体制は一切記載しない。**

【見出し方向性】
「支援の流れ」「NEXORA AIが伴走するステップ」等、プロセスを示す見出し。

【使用可能な確定情報】
上記5つの確定特徴とその順序。

【AIによる提案】
「STEP 1」〜「STEP 5」という**番号表示は使用可**(日数・期間は使用しない)。各ステップを接続線・矢印・ノードでつないだ「connected workflow visualization」として視覚化する。

【ビジュアル要素の想定】
Dark Navy〜Blueの背景に、5つのノード(円形または角丸カード)を接続線でつなぐワークフロー図。各ノードにはSTEP番号+短いラベル(例: STEP1「業務ヒアリング」、STEP2「AI活用設計」、STEP3「導入支援」、STEP4「活用支援」、STEP5「運用サポート」)のみを表示し、期間・所要時間は表示しない。接続線にglow/gradientをあしらい、AI/テック的な質感を出す。

【Mobile再構成方針】
横一列のワークフロー図はMobileでは縦方向の1列(上から下へ接続線でつながるタイムライン風)に再構成する。ノードは375pxでも文字が窮屈にならないサイズを確保する。

【CTA】
なし。

【次セクションへの役割】
支援の全体像を理解したうえで、より具体的な特徴(FEATURES)へつなぐ。

### SECTION 05：特徴(FEATURES・Bento Grid)

【目的】
確定特徴を、単なる均等3カードではなく、情報の重要度・性質に応じたサイズ差のあるBento Gridで見せ、視覚的な作り込み感を出す。

【この時点の読者心理】(仮説)
「具体的に何をしてくれるのか、機能面を確認したい」。

【伝える情報】
業務ヒアリング / AI活用方法の提案 / 業務フローに合わせた導入支援 / AIツール活用支援 / 導入後の運用サポート / オンライン相談、の6項目。

【見出し方向性】
「NEXORA AIの特徴」等、機能一覧であることを示す見出し。

【使用可能な確定情報】
上記6項目。

【AIによる提案・Bento Grid構成】
6項目を均等サイズにせず、以下のような大小混在のグリッドを提案する(最終的なグリッド定義はSTEP06で確定)。
- **大カード(2×1相当)**: 「業務ヒアリング」— コアポジショニングの起点であるため最も大きく配置し、簡単な説明文とアイコン/ミニビジュアルを添える
- **大カード(2×1相当)**: 「業務フローに合わせた導入支援」— 差別化ポイントとして大きめに配置
- **中カード**: 「AI活用方法の提案」
- **中カード**: 「AIツール活用支援」
- **中カード**: 「導入後の運用サポート」
- **小カード**: 「オンライン相談」— 補助的な特徴として小さめに配置し、無料相談への接続を匂わせる

各カードは、gradient border・subtle glassmorphism・hover時のglow/lift等の演出を持たせ、カードごとに背景の濃淡や装飾密度を変化させることで単調さを避ける。

【ビジュアル要素の想定】
背景はBackground(白またはごく淡いダークグレーのいずれかをSTEP06で確定)。カードは線画アイコン+短い見出し+説明文。数値・グラフは使用しない。

【Mobile再構成方針】
Bento Gridは375〜430pxでは1カラムの縦積みに再構成する。大カード・中カード・小カードの区別は、Mobileでは「上下のpadding・フォントサイズの差」で表現し、複雑なグリッド構造は維持しない。

【CTA】
なし(直後のSECTION06で中間CTAを配置するため)。

【次セクションへの役割】
特徴を理解した直後の関心が高いタイミングで、中間CTAへ接続する。

### SECTION 06：中間CTA

【目的】
支援内容への理解が進んだタイミングで、無料相談への行動を後押しする。

【この時点の読者心理】(仮説)
「悪くなさそうだ、もう少し詳しく話を聞いてみようか」という前向きな関心。

【伝える情報】
CTA文言のみ、または短い一言の後押しコピーを添える。

【使用可能な確定情報】
CTA文言(無料相談を申し込む)。

【AIによる提案】
FEATURESセクションの余韻を活かし、独立した短いCTAバンド(帯状のセクション)として設計する。過度な装飾は避け、視線がCTAボタンに集中するシンプルな構成とする。

【ビジュアル要素の想定】
Blue〜Cyanのgradientバンド、または枠線のみのシンプルなカード。

【Mobile再構成方針】
CTAボタンは375px幅でも文言が1行に収まるよう、STEP06でフォントサイズ・paddingを検証する。

【CTA】
あり。「無料相談を申し込む」(2箇所目のメインCTA)。

【次セクションへの役割】
まだ検討段階の読者向けに、次のセクションで具体的な活用イメージを補足する。

### SECTION 07：活用イメージ(USE CASE / USAGE IMAGE)

【目的】
実績としてではなく、「こんな業務の整理から相談できる」という仮想的な活用イメージを持ってもらう。

【この時点の読者心理】(仮説)
「自社の場合、具体的に何を相談できるのか」を知りたい。

【伝える情報】
**実在企業の導入事例・成功事例は一切使用しない。** client-brief.mdに具体的な対応業務(営業・人事・経理・カスタマーサポート等)の確定情報がないため、業務例を挙げる場合は「サービスの対応実績」としてではなく、**明確に「例示」であることが分かる構成**にする(見出し・注記の両方で例示である旨を示す)。

【見出し方向性】
「こんな業務の整理から相談できます」「AI活用を考える業務の例」等、実績ではなく例示であることが伝わる見出しを採用する。

【使用可能な確定情報】
業務ヒアリングから始まるという確定特徴のみ。具体的な業務名はclient-brief.mdに確定情報がないため、**STEP05のコピー執筆時に「あくまで一般的な例」である旨の注記を必ず添えることを条件に**、一般的によく話題になる業務領域(例: 問い合わせ対応、資料作成、データ整理等)を"例示"として扱うことを提案する。断定的な実績表現は用いない。

【AIによる提案】
ブラウザウィンドウ風のモックアップ、またはワークフローカードの形式で2〜3個の"活用イメージ"を提示する。各カードに「例」であることを示す小さなラベル(例: 「活用イメージ(例)」)を明記する。

【ビジュアル要素の想定】
Browser window mockup風のフレーム内に、抽象的な業務整理のイメージ(付箋・フローチャート風の簡易図)を表示する。実在アプリのUIを模倣しない。

【Mobile再構成方針】
2〜3枚のカードは375pxで縦積みの1カラムに再構成する。

【CTA】
なし。

【次セクションへの役割】
活用イメージを踏まえ、導入後のサポート内容(SUPPORT)へ接続する。

### SECTION 08：導入後のサポート(SUPPORT)

【この時点の読者心理】(仮説)
「導入後、使いこなせず終わってしまわないか」という不安。

【伝える情報】
導入後の運用サポートという確定特徴。**「定着保証」「必ず使える」等の保証表現は使用しない。**

【見出し方向性】
「導入後も、伴走します。」等、継続的な支援があることを示す見出し(保証を意味しない表現)。

【使用可能な確定情報】
導入後の運用サポート、AIツール活用支援。

【AIによる提案】
「support system diagram」として、中心にNEXORA AI、周囲に「導入後の相談」「活用支援」等の要素を配置した簡易な関係図で表現する。

【ビジュアル要素の想定】
中心ノード+周囲を囲む複数の小ノードという構成。glow・接続線でつなぎ、SECTION04のワークフロー図とは異なる「放射状」のレイアウトにすることで視覚的な変化を作る。

【Mobile再構成方針】
放射状レイアウトはMobileでは中心ノード+縦積みのリストに再構成する。

【CTA】
なし。

【次セクションへの役割】
残った個別の疑問をFAQで解消する。

### SECTION 09：FAQ

【目的】
個別の疑問を解消し、最後の後押しをする。

【伝える情報(確定情報で回答可能なもののみ、6問)】
1. どのような相談ができますか？
2. まだAI導入の方針が決まっていなくても相談できますか？
3. 導入後のサポートはありますか？
4. オンラインで相談できますか？
5. 無料相談はありますか？
6. どこから申し込めますか？

【回答方針(確定情報のみ、STEP05で文面化)】
1. 業務ヒアリングやAI活用方法の提案など、業務に合わせた相談ができる旨(確定情報の範囲)
2. 方針が決まっていない段階でも、業務ヒアリングから相談できる旨(確定情報の範囲。「まだ何も決まっていなくても歓迎」等の強い誘引表現は避け、事実の範囲で回答する)
3. 導入後の運用サポートがある旨
4. オンライン相談に対応している旨
5. 無料相談がある旨
6. Webから申し込める旨

【実案件では追加確認が必要(現時点では回答を作らない)】
- 料金はいくらか
- 相談の具体的な所要時間
- 対応可能な業種・業務の範囲
- 相談から導入までの具体的な期間

【AIによる提案】

- **セクション順**: HERO → PROBLEM → INSIGHT/CONCEPT → SOLUTION/HOW IT WORKS → FEATURES(Bento Grid) → 中間CTA → USE CASE → SUPPORT → FAQ → FINAL CTA → FOOTER(全11セクション)
