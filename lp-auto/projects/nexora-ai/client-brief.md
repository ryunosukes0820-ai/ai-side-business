デザイン品質の目標：
「自主制作の練習LP」ではなく、「実案件で企業に提出しても違和感がないBtoB SaaSサービスサイト」の完成度を目指す。FLEXIA・LUMIELよりも1段階上のデザインクオリティを狙う。単純なカード並び・テンプレート感の強い一般的なLPにはしない。

ファーストビューの方向性：
左にキャッチコピー・サブコピー・CTA・補足、右にAI業務フローを表現するダッシュボード風UI/SaaSプロダクト画面風ビジュアルを配置する構成を軸とする。背景はDark Navy・Blue・Cyanを基調に、subtle gradient・glow・blur・grid・light particle・抽象的なテクノロジーパターンを組み合わせる。ただしSF映画的な過剰な未来感にはせず、企業が実際に導入を検討できそうなリアルなBtoBデザインにする。

UI表現の方向性：
Dashboard mockup・Workflow diagram・AI task automation flow・Analytics card・Integration card・Browser window mockup・Status indicator・Process visualization・floating UI cards・subtle glassmorphism・gradient border・glow effectなどを積極的に使用してよい。ただし数値実績は表示しない。表示する場合はAUTOMATION/WORKFLOW/AI ASSIST/INTEGRATION/PROCESS/SUPPORT等、実績数値を必要としない抽象的なラベルにする。

セクション構成の方向性：
LP全体を単調にせず、セクションごとに背景色・レイアウト・カードサイズ・余白・UI表現を変え、スクロールするほど変化がある構成にする。候補: HERO/PROBLEM/SOLUTION/HOW IT WORKS/FEATURES/USE CASE/SUPPORT/FLOW/FAQ/FINAL CTA/FOOTER。HOW IT WORKSは「業務整理→AI活用設計→導入支援→運用サポート」を視覚的なフローとして表現する。FEATURESは単純な3カード羅列だけでなく、サイズ違いのBento Gridも検討する。

モーションの方向性：
scroll reveal・hover lift・glow transition・card floating・subtle background animation等の控えめなモーションを使用してよい。動きすぎて読みづらくしないこと。`prefers-reduced-motion`に対応する。

レスポンシブの方向性：
Desktopだけでなく、Mobile(375〜430px)でも「作り込まれている」印象を維持する。特にHERO・Dashboard UI・Bento Grid・Workflow・CTA・FAQを重点的に確認し、横スクロールを発生させない。

参考サイト：
未設定(AI SaaS企業・BtoBスタートアップ・業務効率化SaaS・クラウドサービス・モダンなテック企業の公式サイトを参考イメージとする)

避けたいデザイン：
- FLEXIA案件のような黒一色の高級感デザイン
- LUMIEL案件のような明るく親しみやすい教育サービス系デザイン
- 派手すぎるSF的表現

- 根拠のない実績・数値を強調する演出(UIモックアップ内の数値表示を含む)
