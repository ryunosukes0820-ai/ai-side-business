# FLEXIA Design Guide

本文書は、STEP07完了後のHTML/CSS/JS実装工程でそのまま参照できるデザイン仕様書である。画像生成・実装はまだ行わない。使用コピーは`05_lp_copy.md`の採用コピーに準拠する。

## 1. デザインコンセプト

**「都会で働く男性に向けた、静かな強さと洗練を感じるパーソナルジムLP」**

- **どんな印象を与えるか**: 落ち着いた自信、都会的でスタイリッシュ、余白を活かした高級感。派手さより「静かな説得力」を重視する
- **何を避けるか**: 赤×黒の攻撃的なジムデザイン、ネオン装飾、過度なマッチョ表現、安売り感のある演出、情報過多なレイアウト

## 4. レイアウトシステム

- **最大コンテンツ幅**: 1160px
- **PC左右余白**: 40px
- **タブレット左右余白**: 32px
- **SP左右余白**: 20px
- **セクション上下余白**: PC 120px / タブレット 88px / SP 64px
- **カード間gap**: 24〜28px
- **grid基本ルール**: CSS Gridベース。カードグリッドは`repeat(auto)`ではなく明示的な列数指定(3列/2列/1列)で管理し、意図しない折り返しを防ぐ
- **border-radius**: カード16px、ボタン999px(ピル型)、小要素(タグ等)8px
- **shadow**: 明背景カード `0 12px 32px rgba(20,23,28,0.08)`。暗背景セクションでは影ではなくボーダー(`Border Inverse`)で区切る
- **container設計**: `.container { max-width: 1160px; margin: 0 auto; padding: 0 var(--space-side); }`

**ブレークポイント**: Desktop ≥1024px / Tablet 768〜1023px / Mobile ≤767px

## 5. ファーストビュー(SECTION 01)

**使用コピー**: メインコピー「忙しい毎日に、週2回のトレーニング習慣を。」/ サブコピー「完全マンツーマンだから、迷わない。仕事帰り60分から始めるパーソナルトレーニング。」/ 補足コピー「完全マンツーマン ／ 1回60分 ／ 週2回想定」/ CTA「無料カウンセリングを予約する」

- **PCレイアウト**: 2カラム。左=英字ラベル+メインコピー+サブコピー+補足コピー+CTA、右=メインビジュアル(IMAGE01)。背景はDark(`Primary Dark`)
- **SPレイアウト**: 1カラム縦積み。英字ラベル→メインコピー→サブコピー→CTA→補足コピー→ビジュアル(縮小 or 背景装飾程度)の順
- **コピー配置**: 左揃え、メインコピーを最大サイズで配置
- **CTA配置**: サブコピー・補足コピー直下、左揃え
- **ビジュアル配置**: 右カラム、縦方向中央
- **背景**: Dark。右下または背景全体にごく淡いブルーのグラデーション/ジオメトリックライン(IMAGE01と統合)を配置し、単調な黒一色を避ける
- **英字ラベルの扱い**: ブランド名を英字ラベル「FLEXIA PERSONAL GYM」としてメインコピー上部に小さく配置(letter-spacing広め、uppercase)
- **情報量**: メインコピー・サブコピー・補足コピー・CTAのみに絞り、詰め込みすぎない
- **画面高さ**: `min-height: 88vh`程度を目安とし、100vh固定にはしない(コンテンツ量に応じて自然な高さにする)
- **スクロール誘導**: 必須ではないが、画面下部中央に控えめな「Scroll」ラベル+縦線程度の軽い誘導を検討可(なくても成立する)

**ビジュアル方向性**: 人物写真(実写)ではなく、**抽象的なシルエット表現+ジオメトリックなブルーのアクセントライン**を第一候補とする。理由: 実在人物・実在トレーナーとの誤認を避けられる、高級感・都会的なトーンと相性が良い、STEP07での画像生成リスク(実在人物のような写実表現)を避けられるため。

**対象**: 「無料カウンセリングを予約する」

| 項目 | 値 |
|---|---|
| 背景色(通常) | `--color-accent`(`#2B67F6`) |
| 背景色(SECTION10のみ反転) | 白背景+Accent文字 |
| 文字色 | `#FFFFFF`(反転時は`#2B67F6`) |
| font-weight | 700 |
| padding(PC) | 18px 40px |

## 9. アイコン方針

**方向性**: シンプルな線画(ストローク)アイコンで統一する。単色(Accent BlueまたはInverseカラー)、過度にカラフルな塗りつぶしアイコンは使用しない。

**実装方針**: 外部アイコンライブラリへの依存を増やさないため、必要なアイコン(人物・カレンダー・時計・食事・レンタル・チェック・シェブロン等、10種類前後)はインラインSVGとして自作・軽量化して用意する。著作権リスクのある既存アイコンセットの流用は避ける。

## 10. 画像・ビジュアル方針(STEP07へ引き継ぎ)

必要な画像は**3点**とする(LPの大半はタイポグラフィ・アイコン・カードで構成されるため、画像点数を抑えられる)。

- **IMAGE01**: FVメインビジュアル。抽象的な人物シルエット+ジオメトリックなブルーのアクセントライン。横長〜縦長(4:5程度)。背景はダークニュートラル
- **IMAGE02**: SECTION06ベネフィット用。運動習慣を生活に取り入れた落ち着いたシーンを抽象的・半シルエットで表現。正方形または4:5
- **IMAGE03**: SECTION07利用イメージ用。マンツーマン指導を連想させる抽象的な2人のシルエット構図。横長(16:9〜4:3)

**人物表現の注意点(全画像共通)**:
- 実在人物・実在トレーナーと誤認されない、顔の特徴が強調されない構図(シルエット・後ろ姿・体の一部のクローズアップ等)にする
- ブランドロゴ入りの衣服を作らない
- 実在ジムのロゴ・特徴的な店舗デザインを再現しない
- 過度な筋肉表現を避け、都会で働く会社員層に自然に見える体型にする

## 11. アニメーション・インタラクション

- **fade-up**: 各セクション・カードがビューポートに入った際に、`opacity: 0 → 1` + `translateY(24px) → 0`で軽くフェードイン(IntersectionObserverベース)
- **subtle hover**: カード・ボタンのホバー時に`translateY(-2〜4px)`+shadow強調程度の控えめな動き
- **FAQ accordion**: `max-height`のCSSトランジションで開閉(0.25s ease程度)
- **header transition**: スクロール時にヘッダー背景の透明度・影をわずかに変化させる程度(headerは元々Dark系のため、過度な変化は不要)

**避けるもの**: パララックス、激しいスクロール演出、動画の自動再生、点滅、重いJavaScriptライブラリの導入

**`prefers-reduced-motion`への配慮**: このメディアクエリが有効な場合、fade-up等のtransform/opacityトランジションを無効化し、要素を最初から表示状態にする。

| セクション余白 | 120px | 88px | 64px |
| 画像比率 | 各画像規定比率を維持 | 同左 | 高さを抑えたトリミング(object-fit: cover) |

**Mobile最重要事項**:
- `overflow-x: hidden`または適切なbox-sizingで横スクロールを発生させない
- CTAボタンは高さ48px以上を確保しタップしやすくする
- 見出しは`clamp()`等で長すぎる折り返しを防ぐ
- 画像は`max-width: 100%`、高さを抑えて大きくしすぎない

## 13. アクセシビリティ

- **コントラスト**: 本文・見出しとも背景とのコントラスト比4.5:1(大きな見出しは3:1)以上を実装時に確認する
- **focus-visible**: すべてのボタン・リンク・アコーディオントリガーに明確なフォーカスリングを設定する(色は背景に応じて`--color-accent`または白)
- **alt属性**: IMAGE01〜03すべてに、内容が分かる代替テキストを設定する(装飾目的のみの要素は`alt=""`+`aria-hidden="true"`)
- **button/anchorの使い分け**: ページ内遷移・フォーム送信は`<button>`、別ページ・別セクションへのリンクは`<a>`を使用する
- **FAQのaria属性**: トリガーに`aria-expanded`、パネルに対応する`id`と`aria-controls`を設定する
- **keyboard操作**: すべての操作要素をTabキーで到達可能にし、アコーディオンはEnter/Spaceで開閉できるようネイティブ`<button>`を使用する
- **`prefers-reduced-motion`**: 上記11章の通り、アニメーションを無効化するフォールバックを用意する
