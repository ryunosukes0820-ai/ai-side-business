# Social Promotion プロンプト

**目的**: 公開済みのnote記事(published記事本文)をもとに、X(旧Twitter)・Threads向けの宣伝投稿文を作成する。

**承認回数の削減について**: `social/article-XX-promotions.md`はWriteで1回にまとめて作成する。promotions.csvへの登録・git保存は個別コマンドではなく`scripts/complete_publish.py`にまとめる(詳細はCLAUDE.mdの「絶対に守ること」11番)。

**この工程は「公開完了」処理の標準工程、および「SNS宣伝を作成 &lt;article_id&gt;」トリガーの両方で使用する。**

## 絶対に守ること

- **SNSへの自動投稿・予約投稿・API接続は一切行わない。** 作成するのはテキストのみで、実際の投稿はユーザーが手動で行う
- X APIキー・Threads APIキー・アクセストークンなどの認証情報の取得・保存は行わない
- **記事本文に実際に書かれている内容だけを使う。** 記事にない実績・数字・経験・成果を新しく作らない(例: 記事に事実がないのに「○万円稼げた」のように書かない)
- **禁止表現**: 「必ず稼げる」「絶対に成功する」「誰でも稼げる」「100%成果が出る」、虚偽の実績、過度な煽り・誇張表現
- 金融・健康・美容などのジャンルでは、特に断定表現を避ける(記事本文で使っている慎重な表現・注意書きのトーンを踏襲する)
- **XとThreadsで同じ文章をそのまま使い回さない。** プラットフォームごとに文章を変える
- X側の5投稿の中でも、同じ言い回しを繰り返さない

## X用(5パターン)

1. 公開直後用
2. ノウハウ単体型
3. 共感・悩み型
4. 再告知型
5. 短文CTA型

**文字数目安**: URLを除いた本文は100〜220文字程度。短文CTA型はさらに短くしてよい。
**ハッシュタグ**: 原則1〜3個。無理に大量のハッシュタグを付けない。

## Threads用(5パターン)

1. 公開直後用
2. 共感型
3. 学び共有型
4. ノウハウ型
5. 再告知型

**文字数目安**: 180〜320文字程度。Xより少し長めにする。短い段落に分け、会話・共感・読みやすさを重視する。Xの文章をそのまま使い回さない。

## 文字数についての考え方

上記の文字数目安は、あくまで参考の目安であり、厳密な必須条件ではない。以下を優先する。

- 自然さ・読みやすさ・情報価値を優先する。文字数のためだけに不自然な文章にしない
- 文字数を満たすためだけの水増し(不要な言い換え・繰り返し・冗長な説明の追加)は禁止
- 必要な内容が十分に伝わっていれば、多少目安の範囲外であっても、それを理由に再編集を繰り返さない

## 各投稿に含める要素(X・Threads共通)

- **post_type**: 投稿の種類(上記パターン名)
- **おすすめ投稿タイミング**: 下記「投稿タイミング」を参照して割り当てる
- **冒頭フック**: 読者の目を止める最初の一文
- **完成した投稿本文**: そのままコピーして投稿できる完成形のテキスト(冒頭フックを含む)
- **CTA**: note記事へ読みに行ってほしいという呼びかけ
- **記事URL**: 公開されたnote記事のURL(投稿本文に適切に含める)
- **推奨ハッシュタグ/推奨タグ**: X 1〜3個、Threads も同程度

## 投稿タイミング

記事公開日を基準に、以下の目安で使い分けを提案する。実際の予約投稿・自動投稿は行わない。

- **公開直後** → 公開直後用
- **翌日** → ノウハウ型または共感型
- **3日後** → 学び共有型またはノウハウ単体型
- **7日後** → 再告知型
- 必要に応じて短文CTA型も、タイミングを問わず随時使えるものとして提案する

## 保存先

### 1. `social/article-XX-promotions.md`

`XX`は記事id(article_id)を2桁ゼロ埋めしたもの(例: 記事9なら`article-09-promotions.md`)。X5パターン・Threads5パターンをすべて、以下の形式でMarkdownとして保存する。

```markdown
# 記事XX SNS宣伝パッケージ

対象記事: {{記事タイトル}}
記事URL: {{note記事URL}}

## X

### 1. 公開直後用

- post_type: 公開直後用
- おすすめ投稿タイミング: 公開直後
- 冒頭フック: ...
- 完成した投稿本文: ...
- CTA: ...
- 記事URL: ...
- 推奨ハッシュタグ: #... #...

(以下、ノウハウ単体型・共感・悩み型・再告知型・短文CTA型を同形式で)

## Threads

### 1. 公開直後用

(Xと同形式で、Threadsの5パターン分)
```

### 2. `social/promotions.csv`

1記事につき10行(X5行+Threads5行)を登録する。列は `article_id,article_title,platform,post_type,article_url,recommended_timing,status,posted_at`。`platform`は`x`または`threads`(小文字)。`status`の初期値は`ready`、`posted_at`は空欄。

行の登録は `scripts/manage_promotions.py add` コマンドを使う(1行ずつ)。同じ `article_id + platform + post_type` の組み合わせが既に存在する場合、そのコマンドは重複登録しない。既存行は削除・上書きしない。

## 必須チェック

- [ ] X・Threadsとも5パターンずつ、合計10投稿を作成したか
- [ ] 各投稿に、post_type・おすすめ投稿タイミング・冒頭フック・完成した投稿本文・CTA・記事URL・推奨ハッシュタグが揃っているか
- [ ] X本文(URL除く)は100〜220文字程度、Threads本文は180〜320文字程度が目安になっているか(いずれも厳密な必須条件ではなく目安であり、自然さ・読みやすさ・情報価値を優先する。文字数合わせのための水増しはしない。内容が十分伝わっていれば、多少目安の範囲外でも再編集を繰り返さない)
- [ ] 記事本文にない実績・数字・経験・成果を新しく作っていないか
- [ ] 禁止表現(必ず稼げる、絶対に成功する、誰でも稼げる、100%成果が出る、虚偽の実績、過度な煽り)を使っていないか
- [ ] 金融・健康・美容などのジャンルで、断定表現を避けているか
- [ ] XとThreadsで同じ文章を使い回していないか。X内の5投稿でも同じ言い回しを繰り返していないか
- [ ] `social/article-XX-promotions.md` に保存し、`social/promotions.csv` に10行登録したか(重複登録していないか)
